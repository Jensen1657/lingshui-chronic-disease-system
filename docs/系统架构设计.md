# 陵水县人民医院慢病管理系统 — 系统架构设计

> 依据《县域慢病管理中心建设·总体方案和评价标准》要求设计
> 版本：v1.0 | 日期：2026-05-21

---

## 一、系统定位

本系统面向**县域慢病管理中心**，覆盖县、乡、村三级医疗机构协同共管，管理**高血压、糖尿病、冠心病、脑卒中、慢阻肺、慢性肾脏病**6类重点慢病，实现筛查→诊断→风险评估→治疗→随访→转诊→年度评估全周期管理。

## 三、技术栈选型

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 前端 | Vue 3 + Element Plus + TypeScript | 适配县级/基层医生操作习惯 |
| 移动端 | 微信公众号 + 微信小程序（uni-app） | 患者端，与医生端数据互通 |
| 后端 | Python 3.12 + FastAPI + SQLAlchemy | 快速开发，适合医疗业务 |
| 数据库 | PostgreSQL 16 + Redis 7 | 关系型+缓存，支持JSONB存动态表单 |
| 消息队列 | Redis Streams | 随访提醒、预警推送 |
| 文件存储 | MinIO（私有化部署） | 检查报告、随访录音存储 |
| 接口标准 | HL7 FHIR R4 + 自定义REST | 对接全民健康信息平台 |
| 部署 | Docker Compose（本地化）/ K8s（私有云） | 支持离线运行 |
| 安全 | HTTPS + JWT + 数据加密（AES-256） | 符合等保2.0要求 |

## 四、核心模块设计

### 4.1 患者主索引模块（EMPI）

**功能**：为每位患者生成全县唯一的慢病管理主索引，支持跨机构档案合并。

**关键字段**：
- `patient_id` UUID 主键
- `id_card` 身份证号（唯一索引）
- `name`, `gender`, `birth_date`
- `village_code` 行政村编码
- `manage_org_code` 管理责任机构编码
- `disease_list` 患有的慢病类型数组 `['HYPERTENSION', 'DIABETES', ...]`
- `risk_level` 综合风险等级

---

### 4.2 专病管理模块（6类疾病各建子模块）

每类疾病包含相同的**业务子流程**：

```
筛查 → 诊断 → 风险评估 → 制定治疗方案 → 随访 → 转诊（上转/下转） → 年度评估
```

#### 高血压（HYPERTENSION）— 核心规则

| 功能点 | 实现规则 |
|--------|----------|
| 心血管风险分层 | 自动计算，匹配《总体方案》表5 |
| 药物治疗推荐 | 关联表6（六类药物适应人群）、表7（合并症用药方案） |
| 随访计划 | 未达标：2-4周；达标：3个月；血压异常自动预警 |
| 靶器官检查 | 必填：心电图、UACR、超声心动图、颈动脉超声 |

#### 糖尿病（DIABETES）— 核心规则

| 功能点 | 实现规则 |
|--------|----------|
| 诊断标准 | WHO 1999 标准 + 糖化血红蛋白 ≥ 6.5% |
| 糖尿病风险评分 | 自动计算，≥ 25分强制提示行OGTT |
| 心血管风险分层 | 匹配表13 |
| 综合控制目标 | 自动比对表14 |
| 首选用药 | 二甲双胍；合并ASCVD/CKD优先选GLP-1RA/SGLT2i |

#### 冠心病（CORONARY_HEART_DISEASE）

- TIMI评分、GRACE评分自动计算
- PCI术后/ACS患者双抗治疗时长是12个月自动标记
- 血脂目标：ACS患者 LDL-C < 1.8 mmol/L，极高危 < 1.4 mmol/L

#### 脑卒中（STROKE）

- FAST/BEFAST识别工具内置，一键生成转诊提醒
- 强制随访时间点：出院后3月、6月、1年
- 随访内容：神经功能（NIHSS）、康复评估、用药核查

#### 慢阻肺（COPD）

- mMRC呼吸困难分级、CAT评分自动计算 → 匹配GOLD分级（表27）
- 高危人群自动提示做肺功能检查
- 随访频次：FEV₁ < 50% 每年4次，≥ 50% 每年2次

#### 慢性肾脏病（CKD）

- eGFR自动计算（CKD-EPI公式），CKD分期（表33）、危险分层（表34）
- 年度检查自动提醒：尿常规、UACR、肾功能、电解质、泌尿系B超

### 4.3 随访引擎模块（核心）

**随访计划自动生成规则**（匹配《总体方案》表37）：

```python
def generate_followup_plan(patient, disease_type):
    risk = get_risk_level(patient, disease_type)
    control_status = get_control_status(patient, disease_type)
    
    if not control_status:  # 未达标
        interval_days = 14  # 2周
        if disease_type == 'HYPERTENSION' and patient.bp_systolic >= 180:
            send_urgent_alert(patient)  # 紧急预警
    else:  # 达标
        interval_days = 90  # 3个月
    
    # 特殊疾病随访频次
    if disease_type == 'COPD':
        fev1 = patient.latest_spirometry.fev1_percent
        interval_days = 30 if fev1 < 50 else 90
    
    return create_followup_task(patient, disease_type, interval_days)
```

**随访方式支持**：
- 门诊随访（医生端录入）
- 村医上门（APP端录入）
- 电话随访（系统记录）
- 患者自助上报（小程序端）

**随访真实性校验**：
- 定位打卡（村医上门必选）
- 随访录音上传（可选）
- 设备数据自动上传（血压计、血糖仪直连）

### 4.4 双向转诊闭环模块

#### 上转（村级/乡级 → 县级）

```
发起上转 → 自动填充患者病史/用药/近期检查 → 匹配上转标准（表8/17/25/26/31/36）
→ 符合条件 → 推送至县级医院 → 记录上转时间
→ 不符合条件 → 弹窗拦截，提示不符合原因
```

#### 下转（县级 → 乡级/村级）

```
县级制定下转方案 → 自动同步至接收机构
→ 包含：后续用药方案、随访频次、复查项目要求
→ 下转确认 → 记录下转时间
```

#### 转诊追踪

- 转诊状态机：`PENDING → ACCEPTED → IN_TREATMENT → COMPLETED → RETURNED`
- 超时未接诊：默认2个工作日，超时自动预警
- 转诊后2周内随访记录自动关联

### 4.5 质控与考核模块

#### 自动质控校验规则

| 校验类型 | 规则 |
|----------|------|
| 必填项校验 | 高血压：靶器官检查必填；糖尿病：眼底/足背动脉检查必填 |
| 逻辑校验 | eGFR < 45 → 二甲双胍禁用提醒；双侧肾动脉狭窄 → ACEI/ARB/ARNI禁用 |
| 随访真实性 | 定位打卡 + 随访录音（可配置是否强制） |

#### 考核指标自动统计（匹配《总体方案》第六章）

**管理类指标**：
- 建档率 = 已建档人数 / 辖区内慢病患者总数
- 筛查覆盖率 = 完成筛查人数 / 辖区内高危人群总数
- 个性化评估率 = 完成风险评估人数 / 已建档人数
- 长期管理协议签约率

**效果类指标**：
- 血压/血糖/血脂达标率
- 随访完成率 = 实际完成随访次数 / 应随访次数
- 下转人数增长率

**报告输出**：季度质控报告、年度质控报告，支持导出Word/PDF上报

### 4.6 预警引擎模块

#### 患者维度预警

| 预警类型 | 触发条件 |
|----------|----------|
| 血压危急值 | SBP ≥ 180 mmHg 或 DBP ≥ 110 mmHg |
| 低血糖 | 血糖 < 3.9 mmol/L |
| 高血糖危急值 | 血糖 > 16.7 mmol/L |
| 肾功能恶化 | eGFR下降 ≥ 25%（与上次检查比对） |
| 急性加重 | 慢阻肺急性加重症状识别 |

#### 机构维度预警

- 随访完成率 < 80% → 自动提醒管理机构
- 上转超时未接诊 → 自动提醒

## 五、权限体系设计

依据需求文档，按**角色**配置权限：

| 角色 | 权限范围 |
|------|----------|
| 村卫生室医生 | 随访录入、高危筛查、上转申请 |
| 乡镇卫生院医生 | 患者管理、上转申请、基础报表、下转接收 |
| 县级医院医生 | 诊断调整、下转方案制定、治疗方案审核 |
| 慢病管理中心管理员 | 全量数据查看、考核统计、系统配置 |
| 患者 | 查看自己的健康数据、自助上报 |

**数据权限**：村卫生室只能查看本村患者；乡镇卫生院只能查看本乡镇患者；县级医院可查看全县患者（需审批）。

## 七、数据安全设计

1. **数据归属**：数据归属医院所有，系统厂商无权使用
2. **加密存储**：患者敏感信息（身份证号、手机号）AES-256加密
3. **审计日志**：所有数据访问/修改操作留痕，不可篡改
4. **本地化部署**：支持医院内网部署，数据不出院
5. **等保合规**：满足等保2.0三级要求
